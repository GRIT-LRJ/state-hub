关键读图法：

- **①②③ 是同一个 Runtime 内的三步**：收应用请求 → 问状态机 → 查注册表调驱动。

  而是平台自己的一部分，一手对外（应用接口）、一手对内（驱动调度）。

## 2. 平台与应用之间靠 Runtime 吗？—— 靠，但要说清楚

**是的。** 但对"Runtime"的理解要纠正一个常见误区：

```
你以为的：  应用 ──▶ 平台 ──▶ Runtime ──▶ 驱动        （Runtime 只是平台和驱动之间的桥）
实际是：    应用 ──▶ [ 平台(内含 Runtime) ] ──▶ 驱动   （Runtime 是平台自己的一块）
                     ↑ 对外脸：HTTP 服务     ↑ 对内脸：驱动调度
```

- **应用 → 平台**：应用通过 HTTP 请求到达平台；**这个 HTTP 服务就是 Runtime 写的**。
- **平台 → 驱动**：Runtime 的"驱动宿主"部分负责调度。
- 所以：**Runtime 同时站在平台的两个边界上**：
  - 对外边界：它是"应用接口"的实现者（服务员）；
  - 对内边界：它是"驱动接口"的调用者（调度员）。

> 一句话：**Runtime 是平台内部一条"上接下联"的脊椎——上面接应用、下面管驱动，中间自己调状态机。**

## 3. 注册表（Registry）是什么？

**注册表 = 一张"内存里的花名册"**，用来记住"有哪些驱动、每个驱动是谁、能干什么"。

### 3.1 日常类比

- **班级花名册**：每位同学（驱动）登记姓名/特长（states）；
  老师（Runtime）查花名册就知道"谁会画画"，不用挨个问。
- **Windows 设备管理器**：列出一张表——鼠标、键盘、显卡；
  系统按表去找对应的驱动。**"设备管理器列表"本身就是注册表。**
- **图书馆索引**：书名 → 书架位置；你要哪本书就查索引。

### 3.2 代码里的样子（v1 草案）

Runtime 启动时把每个驱动"登记"进一个 `Map`：

```ts
type RegistryEntry = {
  manifest: DriverManifest;    // 从 driver.json 读进来的声明（含 states）
  instance: Driver;            // 加载后的驱动对象
};

class Runtime {
  // 注册表就是一个 Map：驱动 id → { 声明, 实例 }
  private registry = new Map<string, RegistryEntry>();
}
```

登记后的花名册长这样：

```txt
id        │ 支持的状态                 │ 实例
──────────┼───────────────────────────┼──────────────
virtual   │ completed, decision, none │ VirtualDriver
vk87      │ completed, decision       │ Vk87Driver
pushplus  │ completed, decision       │ PushPlusDriver
```

### 3.3 什么时候"注册"？什么时候"查"？

```
平台启动
  └─ Runtime 扫描驱动目录
       └─ 对每个驱动：读 JSON → Schema 校验 ✅ → 加载代码 → 实例化
            └─ registry.set(id, { manifest, instance })   ← 这一步叫"注册/登记"
运行中
  └─ 收到事件 → 状态机 → currentState
       └─ Runtime 查注册表：谁支持这个状态？
            └─ 命中 → instance.apply(state)                ← 这一步叫"查表 + 调度"
平台关闭
  └─ 对注册表里每个实例 dispose()                          ← "注销/清理"
```

### 3.4 为什么叫"注册表"而不是"列表"

因为驱动是**主动"报名"**的（提供 JSON + 代码），平台**登记**它；
以后平台**按表调度**。这和你熟悉的"注册/登记"概念一致。

## 4. 迷你关系表（可背）

| 角色 | 与平台关系 | 干什么 |
|---|---|---|
| 应用 | 平台之外，调用平台 | 上报状态 |
| Runtime（对外脸） | 平台内部 | 实现 HTTP 应用接口 |
| 状态机 | 平台内部 | 仲裁 → currentState |
| Runtime（对内脸） | 平台内部 | 持有注册表、调度驱动 |
| 驱动注册表 | Runtime 持有 | 记录"谁支持什么" |
| 驱动 | 平台之下，被调用 | 按自己配置执行动作 |
